# Roadmap

Each phase has an exit criterion. A phase isn't done until its criterion is met and measured.

| Phase | Scope | Exit criterion |
|---|---|---|
| **1. Design** | Spec docs 00 to 05, JSON schemas, token benchmark | SSP-T uses fewer tokens than Python on the benchmark median across 3 tokenizers |
| **2. Core compiler** | Rust: SSP-T parser and printer, graph store (SQLite), hashing, type and effect checker, interpreter, ops protocol, diagnostics with fix ops | 10-program suite runs. A model given only the spec writes correct programs for 70% or more of 30 held-out tasks |
| **3. Agent loop** | Query API, context packs, MCP server, typed holes, property tests from contracts, effect handlers, coroutines | An agent completes multi-step feature tasks using ops only, with fewer total tokens than the same agent using Python |
| **4. Native and systems** | Cranelift backend, `sys` profile (ownership, `res`, `Ptr`, `unsafe`), allocator handlers, atomics and threads, comptime, const generics, variadics, specialization, SMT contracts (Z3) | Runtime benchmarks within 1.5x of C++ -O2. Ownership checker passes the soundness suite |
| **5. Release and bare** | LLVM backend, LTO and PGO, SIMD and intrinsics, inline asm, `bare` profile, MMIO and interrupts, C binding generator, embedded targets | Within 1.1x of C++ -O3. Boots a bare-metal hello world on QEMU riscv64 and aarch64 |
| **6. Ship** | Deployer (AWS), effects-as-IAM, migrations, hot swap, replay, `kernel fn` (Metal, SPIR-V, PTX), full std library | A CRUD service goes from intent to production with zero handwritten infra. Std library matches C++ coverage |
| **7. Scale** | CRDT multi-agent sync, global build cache, distributed store, proven rewrites, cost-driven optimization | 100 concurrent agents on one codebase with no lost work |

The first run, with JSON queries and transaction files, was 1.96x. A checker slowdown on nested constructor literals (20s) was fixed (10ms). **Rerun after Phases 4 to 7 (run 4):** still 95/95 on both sides, but the compressed 1.8k spec had dropped rules the tasks need (core List methods, the `catch` test form, the one-edit and file-fallback CLI guidance) and SSPUR rose to 1.24x. With those restored (1,782 tokens) and the 4 affected cells rerun, SSPUR used **0.70x** (median 0.61x, 26 calls vs 38). An optional 9th task with regex and JSON passed 17/17 on both sides at 0.75x after one more spec fix. **Run 5 (more models, neutral tasks, a large codebase):** Opus 5.5 used 0.76x on the 8 tasks (95/95 on both sides) and Sonnet 0.74x on 8 tasks from neutral sources (0.66x after a spec fix, 141/141 on both sides), but Haiku 4.5 used 2.31x (1.21x after the fix; SSPUR 95/95, Python 84/95) and Sonnet used 1.34x on one 1,117-definition codebase. | 4 | Speed criterion met and exceeded: native code beats C++ -O2 on every benchmark (now 0.14x typical, 0.57x strings, 0.59x app, 0.89x compute), with in-place reuse, fusion, and proven check elimination (ADR 0005 to 0008). SMT contracts: `sspur verify` proves `pre`/`post`/`where` with Z3, and native code drops proven checks (ADR 0009). Automatic multi-core parallelism for pure pipelines (ADR 0011). `sys` profile: owned `res` types with destructors, second-class borrows, `Ptr` and the `unsafe` effect; **the ownership checker passes the soundness suite** (68 rejected, 18 accepted programs identical in both tiers; ADR 0012). See `bench/native/`. Since 0.8.2 native code also frees list buffers and strings at their last use when they have one owner (ADR 0033), which puts peak memory near or below C++ on every benchmark but `gpu`. Traits (ADR 0027): `trait` and `impl` with default methods and effect-bounded methods, bounds on type parameters checked at the definition, operator traits and `derive Eq, Ord, Show, Hash, Json`, all resolved statically by specializing bounded functions per type, identical in both tiers and across packages. |
| 5 | Speed criterion met: native code beats C++ -O3 on every benchmark (0.15x to 0.88x; `bench/native/README.md`). **Boot criterion met:** `profile bare` (no runtime; `E_PROFILE_BARE` for heap, log and error features), typed volatile MMIO (`mmio[U32](addr)`), `interrupt timer` handlers, and `sspur build --target riscv64-qemu|aarch64-qemu` (freestanding C, startup file, linker script, clang and ld.lld). `examples/bare/hello.ssp` prints `hello from sspur` and a timer-interrupt example fires on QEMU `virt` for both architectures, checked by `cargo test` (ADR 0017). **Remaining items (ADR 0024):** direct LLVM IR was prototyped for scalars, control flow and records and measured against the C path with the same clang 23 (compute_big 1.04x, the simd kernels as loops 0.98x), so C through clang stays the production backend. `--pgo` trains once and rebuilds with `-fprofile-use` (compute_big 3% faster, others unchanged), `--lto off|thin|full` is explicit (default off). Inline asm `asm "..." in(..) out(..) clobber(..)` under `unsafe` in `sys` and `bare` reads cycle counters on the host and both QEMU machines. `thumbv7em-mps2` builds Cortex-M4 firmware (vector table, startup copy, flash and RAM linker script, SysTick, NVIC) that boots hello, timer and interrupt examples on `qemu-system-arm -M mps2-an386`. Fixed arrays `Array[T, N]` live on the stack, and `static` module state is shared by interrupt handlers and `main` through atomic `load store swap add cas` with the `E_STATIC_RACE` rule. `F64` runs on aarch64-qemu (hardware FPU) and thumbv7em-mps2 (software double precision matching the host bit for bit), and `core_main` runs on a second aarch64 core started with PSCI, sharing atomic statics (ADR 0017 update). Pending: real boards, a board description format, PLIC, MMU, SMP beyond aarch64-qemu |
| 6 | Mostly done. Deployer and effects-as-IAM: `store`, `svc`/`ep`, `db.*` effects compiled natively, and `sspur deploy plan` produces CloudFormation, per-handler least-privilege IAM derived from effect rows, and a native Lambda bootstrap. `sspur deploy local` runs the CRUD example end to end under enforced policies (ADR 0016). Migrations, hot swap and replay (ADR 0019): store schema versions from type hashes, `sspur deploy migrate` classifies changes as compatible, migration (a typechecked `migrate_S` function, optional `unmigrate_S` for side by side) or breaking; handlers migrate lazily on read and a conditional backfill runs locally or as a generated Lambda; `deploy local` hot swaps with weighted canary and rollback, with no failed requests under concurrent load; `--record` and `sspur deploy replay` re-run traffic against a new version and report differences. Real deploys get retained versions, a `live` alias and CodeDeploy canary with alarm rollback, `rollback.sh` and `backfill.sh`. Std library (ADR 0018), two rounds: `Set`, `Heap`, `StrBuf`, `HashMap`/`HashSet` (persistent HAMT, 5.5x faster lookups than `Map`), `Regex` (Pike VM, no backtracking), `BigInt` and fixed-point `Dec`, `Bits`, `Time`/`Duration` (UTC calendar, ISO 8601), Python-style `.format(spec)`, the rest of `<cmath>`, saturating and rotate ops, seeded distributions and `shuffle`, lazy `range` pipelines and loops, `fs` binary I/O and directories, a `proc` effect (`run_cmd`, `exit`), JSON for every data type; a third round adds `FlatMap`, `MdSpan`, lazy `View` values fused into native loops, binomial/Poisson/geometric/gamma/beta/weighted draws and a splittable `Rng`, `Complex`, IANA time zones from the system zoneinfo, streaming `File` handles and Unicode case folding, all identical in both tiers with every suite function native; a fourth round adds `Ratio`, `valarray` idioms as fused pipelines, file copy, symlinks and permission bits, and `Locale` values with bundled collation and formatting for six locales; all 23 C++ library areas are covered. GPU kernels (ADR 0020): `kernel fn` with `@grid`, slice borrows, a device subset checked for races, the `dev` effect and `DevBuf` device buffers; the interpreter runs threads in order with exact `F32`, native code runs Metal (exact `F32`, rerunning on the CPU when a thread could trap or meet a subnormal) with identical results and traps, and `sspur gpu` emits OpenCL C, SPIR-V and PTX. ADR 0023 adds queued launches synchronized on buffer reads, `shared[T](n)` arrays with `barrier()` (uniformity and per-phase race checks), order-independent atomics, `@grid2` 2D grids and inlined pure helper fns. `bench/native/gpu` is 2.6x faster than C++ -O2 overall (0.38x; tiled matmul 8.4x). First real deploy verified on a test account: CRUD over HTTP API, Lambda and DynamoDB, least-privilege roles checked live, then torn down (ADR 0016), and a real canary, backfill and rollback on a test account (ADR 0019). Pending: SLO-driven rollout gates |
| 7 | **Exit criterion met** (ADR 0021): 100 concurrent agents (threads, 8 randomized edits each: add, change and rename functions, attach tests, edit shared functions, with one agent renaming a function all others call) on one codebase through the real transaction path: about 800 transactions, about 700 acknowledged, about 120 conflicts reported to their agents, 0 lost edits, the final codebase typechecks and all its tests pass. Definitions are CRDT registers (stable id, name and body registers), so renames commute with body edits; transactions are optimistic against a base, merged under a file lock with typecheck-on-merge and conflict reports that carry the other side's source and a rebase; the commit sequence is crash safe across processes. Replicas sync by hash over directories or TCP (`sspur sync serve|push|pull|resolve`) and converge under random op and pull orders. Global per-definition check cache in `~/.cache/sspur` (checking part 3.1x faster warm; native `sspur test` re-check 23 s to 0.96 s, also from another codebase). **Per-definition native objects** (ADR 0022): one C unit per definition, cached by content and linked; editing one function of a 200-function program re-tests in 0.93 s instead of 5.2 s, benchmarks unchanged. **Proven rewrites** before codegen (inlining, overflow-aware folding, dead-branch elimination by intervals and Z3, map/map and loop fusion with a trap-order proof), shown by `sspur explain-opt`; native and interpreter stay identical on the corpus and under differential fuzzing. **Cost-driven choices** (inline or call, fused loop or native in-place fusion, profile-guided with `sspur run --profile`): simd 15% faster, typical peak memory 85 MB to 15 MB. Pending: check cache for `sys`/`bare`, an authenticated sync server |

## Language completeness

C++-level completeness is the target. The phase for each feature is in `05-systems-layer.md` section 15. Features land when their phase is reached, but the design of every feature is fixed in Phase 1 so later phases never force a redesign.
