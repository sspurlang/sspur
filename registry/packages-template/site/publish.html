Publish

Publish a package

Pick your public repository and a tag. This page reads the files from GitHub and runs the registry's checks in your browser, then opens the publish request on github.com, where you are signed in. No tokens, no server, nothing sent anywhere but GitHub.

From a terminal, sspur publish in the package does the same, with its tests too.

  1. 1 Your GitHub account

    The package must be a public GitHub repository: the registry, its checks and everyone who installs it read the code from there. A scoped name (acme/money) belongs to the repository's owner: publish it as that user, or as a public member of that organization.

    Or enter a repository and ref yourself

        Submit publish request

        The request opens on github.com as a prefilled form; submitting it there makes it yours. The registry workflow then runs every check again, including the tests, and answers on the request.

      What happens next

      1. RequestSubmitting opens an issue on github.com in your name, with the repository, tag and version filled in.
      2. ChecksThe registry checks the tag again and runs its tests natively and interpreted, then opens a pull request listing every check.
      3. ReviseIf something fails, fix it, move the tag and comment /recheck. The list updates each time.
      4. MergedWhen every check passes it merges, with a snapshot of the source. A new name is approved once by a maintainer first.

      The standards behind every check are in CONTRIBUTING.
